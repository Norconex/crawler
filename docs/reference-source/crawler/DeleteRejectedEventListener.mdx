# DeleteRejectedEventListener

## Summary

Sends deletion requests to the committer when documents are rejected or not found.

## Notes

Listens for crawler rejection events (such as "not found" or "filtered") and sends a deletion request to the committer for the affected document. Useful for keeping the index clean when documents are removed from or filtered out of the source.

The rejections of reference filters, metadata filters and document filters all name the reference, so any of them can trigger a deletion. To avoid deleting what was never sent, set `previouslyProcessedOnly`.

## Properties

### eventMatcher

A text matcher identifying which crawler events trigger a deletion request to the committer. Default matches any event matching the regular expression `REJECTED_.*`.

### previouslyProcessedOnly

When `true`, a deletion request is only sent for a reference that a previous crawl session processed successfully (new, modified, unmodified or not yet due for a recrawl). A reference that was never processed successfully (it was rejected the first time it was encountered, for instance) was most likely never sent to a committer, and one that a previous session already rejected was already asked for, so neither gets a request. That keeps the number of deletion requests to what is needed, and stops the same ones from being sent run after run. This is read from the previous session's ledger, so nothing is deleted on a first crawl. The ledger does not track what each committer received. Default is `false`: every rejected reference gets a deletion request.

## Examples

The following example will send deletion requests whenever a reference  is not found (e.g., a 404 response from a web server) or if it was  filtered out by the crawler.

<ConfigBlock
  json={{
    "class": "DeleteRejectedEventListener",
    "eventMatcher": {
      "method": "CSV",
      "pattern": "REJECTED_NOTFOUND,REJECTED_FILTER"
    }
  }}
/>
