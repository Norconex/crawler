# AdlsGen2Fetcher

## Summary

Azure Data Lake Storage Gen2 fetcher (`abfs://` and `abfss://`).

## Notes

Fetches documents from Azure Data Lake Storage Gen2 using references such as
`abfss://filesystem@account.dfs.core.windows.net/path/to/file`.

Supports:

- Shared key authentication via `credentials`
- SAS token authentication via `sasToken`, or as the `password` of `credentials` that
  have no `username` (see [Keeping a SAS token secret](#keeping-a-sas-token-secret))
- Optional endpoint override via `endpoint`
- Access control lists, from the paths' POSIX-style ACLs, via `acl`

When `endpoint` is not set, the endpoint is derived from the reference account
as `https://<account>.dfs.core.windows.net`.

The credentials username must match the account in the reference URI.

### Keeping a SAS token secret


A SAS (Shared Access Signature) token grants limited access to a storage account: it can be
restricted to one container, to read and list only, and to a period of time, without
revealing the account key. It is what to ask for when the account key cannot be shared.

A token in `sasToken` is part of the configuration as written. To keep it out of it, give it
as the `password` of `credentials` and leave the `username` empty: the fetcher then uses the
decrypted password as the SAS token. Encrypt it with a `passwordKey`, or supply it from a
variable, as for any other password. A `sasToken` in the configuration, if any, wins.

## Properties

### acl

Which permissions to read and write on each file as its access control list (ACL), in the `crawler.acl` field:

- `NONE` (the default): none.
- `BASIC`: the owner, owning group and their rights.
- `EXTENDED`: the named users and groups of the path's ACL too, with its mask.

Entries of the `ACCESS` scope granting `r` allow reading; `other` is `special:everyone`. A `path` level says who may go
through (has `x` on) every folder above the file, the file system's root included. Users and groups are Microsoft Entra
object ids, of the directory `entra:<storage account>`. `DEFAULT` entries only describe what new children get: they are
kept in the ACL's native part. Azure role assignments (such as Storage Blob Data Reader) grant access besides ACLs and
are not read.

The ACL lists who may read the document, as one or more levels a person must all pass; within a level, a deny wins over
an allow. Committers send it as their own `acl` option says. When the permissions could only be read in part, the ACL
is marked partial, and a committer withholds the document unless its `acl.partial` is `SEND`; when they could not be
read at all, it always withholds it. A permission change alone does not change a file's date or size: to have it
noticed, use a metadata checksum that includes `crawler.acl`, such as a `GenericMetadataChecksummer` on the fields
`crawler\.(lastModified|fileSize|acl)`.

### credentials

Username and password used for ADLS Gen2 shared-key authentication:

- Username: storage account name
- Password: storage account key

### domain

The domain name for authentication when accessing the remote resource.

### endpoint

Optional service endpoint override. When omitted, the endpoint is derived from
the reference account.

### proxySettings

Configures an optional HTTP proxy for outbound connections. Leave unset to
connect directly.

### referenceFilters

Filters applied to document references (URLs or file paths) to control which
ones are fetched. Documents whose references do not pass the filters are
skipped.

### sasToken

Optional SAS token used instead of shared-key credentials, kept as is in the configuration.
To keep it secret, leave it empty and give it as the password of `credentials`, with no username.

## Examples

The following example uses shared-key authentication and crawls an ADLS Gen2
file system.

<ConfigBlock
  json={{
    "class": "AdlsGen2Fetcher",
    "credentials": {
      "username": "myaccount",
      "password": "my-account-key"
    }
  }}
/>

The following example uses a SAS token.

<ConfigBlock
  json={{
    "class": "AdlsGen2Fetcher",
    "sasToken": "sv=2025-01-05&ss=bfqt&srt=sco&sp=rl&se=2027-01-01T00:00:00Z&sig=..."
  }}
/>

The following example keeps a SAS token secret. With no `username`, the `password` of the
credentials is the SAS token, so it can be supplied by a variable and encrypted like any
other password.

<ConfigBlock
  json={{
    "class": "AdlsGen2Fetcher",
    "credentials": {
      "password": "${azureSasToken}",
      "passwordKey": {
        "source": "ENVIRONMENT",
        "value": "MY_KEY_VAR"
      }
    }
  }}
/>

The following example reads the access control lists of the paths, named users and groups included.

<ConfigBlock
  json={{
    "class": "AdlsGen2Fetcher",
    "acl": "EXTENDED"
  }}
/>
