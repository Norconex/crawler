# ApacheKafkaCommitter

## Summary

Commit documents to Apache Kafka.

## Notes

Commits crawled documents to an Apache Kafka topic. Supports optional topic creation, field mappings to Kafka fields, and configurable partition and replication settings.

Interoperability note:

- ApacheKafkaCommitter provides Kafka-based interoperability out of the box by
  publishing crawl output to an open event bus.
- This allows downstream integration with a wide range of systems through
  Kafka-native consumers and connector ecosystems.
- Downstream behavior (for example schema mapping, delete semantics,
  idempotency, and ACL handling) depends on the target consumer/connector
  configuration and capabilities.

## Properties

### bootstrapServers

A list of host/port pairs in the form `host1:port1,host2:port2,...` to use for establishing a connection to the Kafka cluster.

### createTopic

Create the "Topic Name" in Kafka if it does not exist already.

### credentials

The user name and password to sign in with when `securityProtocol` is `SASL_PLAINTEXT` or `SASL_SSL`. The password can be encrypted, so it stays out of the configuration.

### fieldMappings

Mapping of source fields to target ones (Kafka fields).

### partitions

Number of partitions set at topic creation.

### queue

Configures the committer queue used to batch documents before sending them to the target system. Adjust queue settings to tune throughput and memory usage.

### replicationFactor

Replication factor set at topic creation.

### restrictions

Defines filter conditions that restrict which documents this committer processes. Documents not matching the restrictions are ignored by this committer.

### saslMechanism

How the client signs in when `securityProtocol` is `SASL_PLAINTEXT` or `SASL_SSL`: `PLAIN` (default), `SCRAM_SHA_256` or `SCRAM_SHA_512`.

### securityProtocol

How the client connects to the brokers: `PLAINTEXT` (the Kafka default, no encryption and no sign-in), `SSL` (encrypted with TLS), `SASL_PLAINTEXT` (sign-in, not encrypted) or `SASL_SSL` (sign-in, encrypted). The sign-in uses `credentials`.

### topicName

The Kafka topic name to possibly create and use as the target for storing documents.

## Examples

The following example uses the minimum required settings to configure Apache Kafka Committer. The Kafka topic won't be created. As such, the topic must already exist in Apache Kafka.

<ConfigBlock
  json={{
    "class": "ApacheKafkaCommitter",
    "bootstrapServers": "http://some_host:1234",
    "topicName": "my-topic"
  }}
  xml={`
    <committer>
      <class>ApacheKafkaCommitter</class>
      <bootstrapServers>http://some_host:1234</bootstrapServers>
      <topicName>my-topic</topicName>
    </committer>`}
/>

The following example signs in to a secured cluster with SASL over TLS, with the password kept encrypted.

<ConfigBlock
  json={{
    "class": "ApacheKafkaCommitter",
    "bootstrapServers": "broker1:9093,broker2:9093",
    "topicName": "my-topic",
    "securityProtocol": "SASL_SSL",
    "saslMechanism": "SCRAM_SHA_512",
    "credentials": {
      "username": "crawler",
      "password": "${kafkaPassword}",
      "passwordKey": {
        "source": "ENVIRONMENT",
        "value": "MY_KEY_VAR"
      }
    }
  }}
/>
