# SolrCommitter

## Summary

Commit documents to Apache Solr search engine (standalone or SolrCloud).

## Notes

Commits crawled documents to an Apache Solr search engine, or a Solr-based product. Documents are sent as JSON over HTTP using the JDK HTTP client (SolrJ is not required). Supports a single node, several nodes with load balancing and failover, and SolrCloud. Also supports field mappings, optional explicit Solr commit control, custom URL parameters, and several authentication options.

This committer is bundled with the web and file system crawler distributions.

### Connection mode

Documents are sent to the Solr core or collection URLs listed in `nodes`, e.g., `http://localhost:8983/solr/mycollection`. The `connectionMode` defines how they are used:

- `SINGLE_NODE`: a single Solr node. This is the default with one node. `HTTP/2` is used for `https` URLs (see `httpVersion`).
- `LOAD_BALANCED`: several Solr nodes. This is the default with more than one node. Updates are spread across nodes. A failing node is set aside for a while and the request is sent to another one.
- `CLOUD`: a SolrCloud cluster. Each node URL ends with the collection name. The nodes hosting the collection are discovered over HTTP (Collections API `CLUSTERSTATUS`) and refreshed periodically. If the cluster state cannot be obtained, or discovered nodes are not reachable, the configured nodes are used. SolrCloud has to be set explicitly. **ZooKeeper connection strings are not supported.**

The deprecated `solrClientType` and `solrURL` are replaced by `connectionMode`, `httpVersion` and `nodes`. They are still honored for now, and translate as follows:

| `solrClientType`                                                                   | Replaced by                                   |
| ---------------------------------------------------------------------------------- | --------------------------------------------- |
| `HttpJettySolrClient`, `HttpJdkSolrClient`, `ConcurrentUpdateJettySolrClient`      | `connectionMode: SINGLE_NODE`                 |
| `LBJettySolrClient`                                                                | `connectionMode: LOAD_BALANCED`               |
| `CloudSolrClient`                                                                  | `connectionMode: CLOUD`                       |
| `HttpSolrClient`, `ConcurrentUpdateSolrClient`                                     | `SINGLE_NODE` and `httpVersion: HTTP_1_1`     |
| `LBHttpSolrClient`                                                                 | `LOAD_BALANCED` and `httpVersion: HTTP_1_1`   |

### Authentication

Sent with every request to Solr:

- Basic authentication: `credentials` (the password can be encrypted).
- Bearer token: `bearerToken` (e.g., Solr JWT authentication plugin). Ignored when `credentials` are set.
- Custom HTTP headers: `headers` (e.g., for an API gateway). They can override the `Authorization` header set by the above.
- TLS: HTTPS connections use the JVM trust store. Use the standard `javax.net.ssl.*` system properties to customize it (including client certificates).

HTTP proxies are those of the JVM (`http.proxyHost`, `https.proxyHost`, ...). Kerberos is not supported.

## Properties

### bearerToken

Bearer token (e.g., JWT) sent as an `Authorization` header with every request. Ignored when `credentials` are set.

### connectionMode

How to connect to the Solr `nodes`: `SINGLE_NODE`, `LOAD_BALANCED` or `CLOUD` (see "Connection mode" above). When not set, it is `SINGLE_NODE` with one node and `LOAD_BALANCED` with several. SolrCloud must be set explicitly.

### connectionTimeout

Maximum time to wait for a connection to be established. Default is 10 seconds.



### credentials

Username and password to a protected Solr (basic authentication).

### fieldMappings

Mapping of source fields to target ones (Solr fields).

### headers

Custom HTTP headers sent with every request, as name/value pairs. A header named `Authorization` replaces the one derived from `credentials` or `bearerToken`.

### httpVersion

HTTP protocol version: `AUTO` (default), `HTTP_1_1` or `HTTP_2`. With `AUTO`, HTTP/2 is used for `https` URLs and HTTP/1.1 for `http` ones.

### nodes

URLs of the Solr core or collection to send documents to, e.g., `http://localhost:8983/solr/mycollection`. For SolrCloud, each URL ends with the collection name. Replaces the deprecated `solrURL`.

### queue

Configures the committer queue used to batch documents before sending them to the target system. Adjust queue settings to tune throughput and memory usage.

### restrictions

Defines filter conditions that restrict which documents this committer processes. Documents not matching the restrictions are ignored by this committer.

### socketTimeout

Maximum time to wait for Solr to respond to a request (a batch of documents). Default is 120 seconds.

### solrClientType

**Deprecated**: use `connectionMode` and `httpVersion` instead (see "Connection mode" above).

### solrCommitDisabled

Disable sending an explicit Solr commit request at the end of every batch sent, relying Solr to perform auto-commit instead.

### solrURL

**Deprecated**: use `nodes` instead. Comma-separated Solr URLs.

### sourceIdField

Document field name containing the value that will be stored in Solr target ID field. Default is the document reference.

### targetContentField

Solr field name to store a document content. Default is "content".

### targetIdField

Solr field name where to store a document unique identifier (source ID field). Default is "id".

### updateUrlParams

Parameters to be added on Solr HTTP calls (e.g., `commitWithin`).

## Examples

Single Solr node:

<ConfigBlock
  json={{
    "class": "SolrCommitter",
    "nodes": ["http://localhost:8983/solr/mycollection"]
  }}
/>

SolrCloud with basic authentication:

<ConfigBlock
  json={{
    "class": "SolrCommitter",
    "connectionMode": "CLOUD",
    "nodes": [
      "https://solr1:8983/solr/mycollection",
      "https://solr2:8983/solr/mycollection"
    ],
    "credentials": {
      "username": "myuser",
      "password": "mypassword"
    }
  }}
/>

Bearer token and custom header:

<ConfigBlock
  json={{
    "class": "SolrCommitter",
    "nodes": ["https://solr.example.com/solr/mycollection"],
    "bearerToken": "eyJhbGciOi...",
    "headers": {
      "X-Api-Key": "abc123"
    }
  }}
/>
