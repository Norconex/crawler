# PdfPageSplitter

## Summary

Split PDFs pages so each pages are treated as individual documents.

## Notes

May not work on all PDFs — encrypted ones in particular.

Each page produced carries a `document.pdf.pageNumber` field and a
`document.pdf.numberOfPages` field. The original PDF is kept alongside its
pages; set `discardOriginal` to `true` to keep only the pages.

To drop the original later in the pipeline instead, reject the documents that
have no page number — those are the containers rather than the pages:

```json
{
  "if": {
    "condition": {
      "class": "BlankCondition",
      "fieldMatcher": { "pattern": "document.pdf.pageNumber" }
    },
    "then": [
      { "handler": { "class": "Reject", "message": "Original PDF container" } }
    ]
  }
}
```

By default this splitter applies only to documents whose content type is
`application/pdf`.

Should be used as a pre-parse handler.

## Properties

### applyToOwnParts

Whether this splitter also applies to the parts it made itself, at any depth, when they come back through the flow. Every part goes through all the handlers again, from the first, so a part that still matches what this splitter splits would otherwise be split again. By default (`false`) this splitter leaves its own parts as they are. Parts made by other splitters are not affected, and conditions still decide whether a part reaches this splitter.

### discardOriginal

Discard the original document after the split is performed.

### label

An optional, user-supplied label for this step in the importer pipeline. It has no effect on processing — it exists purely to help identify this step, for example in large configurations or in the visual configurator.

### parentMetadataMatcher

The fields of the document being split that the documents this splitter makes get a copy of, matched on the field name. By default (`.*`) they get all of them, so a field of the whole document (an author, a department) stays on each part, and a condition on such a field applies to the parts too. Narrow it to copy only some (for example `title|author`), or leave the pattern blank to copy none. Either way, a part gets the fields the splitter itself sets on it (its page number and the number of pages).

### referencePagePrefix

Defines the prefix added before the page number in a document reference. Default is "#" such as:

- https://norconex.com/tests/pdf/dummy.pdf#1
- https://norconex.com/tests/pdf/dummy.pdf#2
- https://norconex.com/tests/pdf/dummy.pdf#3

### unless

A condition a document must not meet for this handler to run. See [Flow Control](../importer-flow-control#when-and-unless-on-a-handler).

### when

A condition a document must meet for this handler to run. By default it is a [ContentTypeCondition](./ContentTypeCondition) for PDF (`application/pdf`), so this handler does nothing to documents of any other content type. Setting `when` replaces that default: to keep the content type check as well, repeat it in an [AllOf](./AllOf). See [Flow Control](../importer-flow-control#when-and-unless-on-a-handler).

## Examples

The following example will split PDFs and will append the page number to the original PDF reference as "#page1", "#page2", etc.

<ConfigBlock
  json={{
    "handler": {
      "class": "PdfPageSplitter",
      "referencePagePrefix": "#page"
    }
  }}
/>
