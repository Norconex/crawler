# XmlStreamSplitter

## Summary

Splits XML document on a specific element.

## Notes

This class is suited for large XML documents. It will read the XML as a stream and split as it is read, preserving memory during parsing. For this reason, element matching is not as flexible as DOM-based XML parsers, such as DOMSplitter, but is more efficient on large documents.

## Element matching
To identify the element to split on, you give the full path to it from the document root, where each element is separated by a forward slash. Let's take this XML as an example:

``` XML   
<animals>
  <species name="mouse">
    <animal>
      <name>Itchy</name>
      <race>cartoon</race>
    </animal>
  </species>
  <species name="cat">
    <animal>
      <name>Scratchy</name>
      <race>cartoon</race>
    </animal>
  </species>
</animals>
```

To split on `<animal>`, you would use this in `path`:

``` XML
/animals/species/animal
```

Should be used as a pre-parse handler.

### Content-types
By default only XML content types are processed; anything else passes through untouched. Use `contentTypeMatcher` to narrow or widen that set.

To restrict this splitter by anything other than content type — a URL pattern, a metadata value — wrap it in an `if` block. See [Importer Flow Control](../importer-flow-control).

## Properties

### applyToOwnParts

Whether this splitter also applies to the parts it made itself, at any depth, when they come back through the flow. Every part goes through all the handlers again, from the first, so a part that still matches what this splitter splits would otherwise be split again. By default (`false`) this splitter leaves its own parts as they are. Parts made by other splitters are not affected, and conditions still decide whether a part reaches this splitter.

### discardOriginal

Discard the original document after the split is performed.

### fieldMatcher

Matches document fields based on specified patterns and methods

### label

An optional, user-supplied label for this step in the importer pipeline. It has no effect on processing — it exists purely to help identify this step, for example in large configurations or in the visual configurator.

### parentMetadataMatcher

The fields of the document being split that the documents this splitter makes get a copy of, matched on the field name. By default (`.*`) they get all of them, so a field of the whole document (an author, a department) stays on each part, and a condition on such a field applies to the parts too. Narrow it to copy only some (for example `title|author`), or leave the pattern blank to copy none. Either way, a part gets the fields the splitter itself sets on it (its reference).

### path

The path to the element to split on.

### unless

A condition a document must not meet for this handler to run. See [Flow Control](../importer-flow-control#when-and-unless-on-a-handler).

### when

A condition a document must meet for this handler to run. By default it is a [ContentTypeCondition](./ContentTypeCondition) for HTML, XHTML and XML types (text/html, application/xhtml+xml, application/xml, image/svg+xml and the other types of the `CommonMatchers.DOM_CONTENT_TYPES` set), so this handler does nothing to documents of any other content type. Setting `when` replaces that default: to keep the content type check as well, repeat it in an [AllOf](./AllOf). See [Flow Control](../importer-flow-control#when-and-unless-on-a-handler).

## Examples

The following example will create one document per animals, based on the sample XML given above.

<ConfigBlock
  json={{
    "handler": {
      "class": "XmlStreamSplitter",
      "path": "/animals/species/animal"
    }
  }}
/>
