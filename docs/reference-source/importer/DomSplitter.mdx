# DomSplitter

## Summary

Splits HTML, XHTML, or XML document on elements matching a given selector.

## Notes

This option builds a full DOM tree from the document content in memory. For large files, be cautious—this can use a lot of memory. For better performance with big files, consider a streaming approach like (e.g., `XmlStreamSplitter`).

The [jsoup](http://jsoup.org/) parser library is used to load a document content into a DOM tree. Elements are referenced using a [CSS or JQuery-like syntax](http://jsoup.org/cookbook/extracting-data/selector-syntax).

### Content-types

By default, this filter applies only to documents with content types specified by the [CommonRestrictions.domContentTypes(String)](https://opensource.norconex.com/importer/v3/apidocs/com/norconex/importer/handler/CommonRestrictions.html#domContentTypes(java.lang.String)) method. You can also define your own content types if they represent files containing HTML or XML-like markup tags.

#### Common content-types:
- application/atom+xml
- application/mathml+xml
- application/rss+xml
- application/vnd.wap.xhtml+xml
- application/x-asp
- application/xhtml+xml
- application/xml
- application/xslt+xml
- image/svg+xml
- text/html
- text/xml

### Parser Handler Compatibility

This functionality can be applied as either a `pre-parse` or `post-parse` handler.

## Properties

### applyToOwnParts

Whether this splitter also applies to the parts it made itself, at any depth, when they come back through the flow. Every part goes through all the handlers again, from the first, so a part that still matches what this splitter splits (a `div` inside a `div`, with `div` as the selector) would otherwise be split again. By default (`false`) this splitter leaves its own parts as they are. Parts made by other splitters are not affected, and conditions still decide whether a part reaches this splitter.

### discardOriginal

Discard the original document after the split is performed.

### fieldMatcher

Matches document fields based on specified patterns and methods

### label

An optional, user-supplied label for this step in the importer pipeline. It has no effect on processing — it exists purely to help identify this step, for example in large configurations or in the visual configurator.

### parentMetadataMatcher

The fields of the document being split that the documents this splitter makes get a copy of, matched on the field name. By default (`.*`) they get all of them, so a field of the whole document (an author, a department) stays on each part, and a condition on such a field applies to the parts too. Narrow it to copy only some (for example `title|author`), or leave the pattern blank to copy none. Either way, a part gets the fields the splitter itself sets on it (its reference).

### parser

Defines using XML or HTML parser.

### selector

XPath expression for splitting nodes.

### sourceCharset

Sets the character encoding of the source document to ensure proper reading and processing.

### unless

A condition a document must not meet for this handler to run. See [Flow Control](../importer-flow-control#when-and-unless-on-a-handler).

### when

A condition a document must meet for this handler to run. By default it is a [ContentTypeCondition](./ContentTypeCondition) for HTML, XHTML and XML types (text/html, application/xhtml+xml, application/xml, image/svg+xml and the other types of the `CommonMatchers.DOM_CONTENT_TYPES` set), so this handler does nothing to documents of any other content type. Setting `when` replaces that default: to keep the content type check as well, repeat it in an [AllOf](./AllOf). See [Flow Control](../importer-flow-control#when-and-unless-on-a-handler).

## Examples

The following example splits contant found in an HTML document, each one being stored within a div with a class named "contact".

<ConfigBlock
  json={{
    "handler": {
      "class": "DomSplitter",
      "selector": "div.contact"
    }
  }}
/>

### content Type

The following example splits content from a field named `embedded_file`, but only when the content type is `text/html`. It targets HTML elements matching the `div.contact` selector within that field

<ConfigBlock
  json={{
    "handler": {
      "class": "DomSplitter",
      "selector": "div.contact",
      "parser": "HTML",
      "contentTypeMatcher": {
        "method": "BASIC",
        "pattern": "text/html"
      },
      "fieldMatcher": {
        "method": "BASIC",
        "pattern": "embedded_file"
      }
    }
  }}
/>
